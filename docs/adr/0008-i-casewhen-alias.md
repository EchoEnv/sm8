# ADR-008-I: `Expr.CaseWhen` + `Expr.Alias` extensions (PR-I)

**Status:** Accepted. **Date:** 2026-08-16. **Author:** SM8 agent (per user directive 2026-08-16: "transform (column like case when, or alias, etc.)").

## Context and Problem Statement

Per the user's 2026-08-16 directive (*"transform (column like case when, or alias, etc.) MUST structure align with RFC based"*), the SM8 reactor's `Expr` ADT was missing two common SQL/relational constructs:

1. **`CASE WHEN cond THEN x ELSE y END`** — conditional expressions. Every SQL engine supports this; the legacy `semanticdf` v0.3.1 design references it as a derived-measure building block (`CalculatedMeasure.expr: Expr` where the expression may be `CASE WHEN condition THEN value ELSE default END`).

2. **`expr AS name`** — column aliases. The lower-level `FieldRef(name)` references an existing column; an `Alias(name, expr)` introduces a NEW column derived from an expression with a given name. Every SQL engine supports this (Spark `Column.as(name)`, Trino `SELECT expr AS name`, DuckDB `SELECT expr AS name`).

After PR-H landed the `rel/` package (the relational-plan tree + join kinds + 16 aggregate fns), the **Expr** ADT was still missing these 2 cases — blocking the user's directive.

**Decision:** PR-I ships 2 new `Expr` cases. PR-J (Model extension) and PR-K (Spark connector compile for joins + aggregates) build on this.

## Decision

### What lands in PR-I

| New case | Shape | Spark compile |
|---|---|---|
| `Expr.CaseWhen(branches: List[(Expr, Expr)], otherwise: Expr)` | conditional expression; first matching branch wins | `functions.when(cond, result).when(...).otherwise(otherwise)` (the entry point is the free function `when`, not `Column.when`) |
| `Expr.Alias(name: String, expr: Expr)` | `expr AS name` | `toColumn(expr).as(name)` |

### Spark compile — the `functions.when` entry-point discovery

The naive approach `Column.when(cond, value)` fails with `IllegalArgumentException: when() can only be applied on a Column previously generated by when() function` (Spark 3.5 contract). The correct pattern:

```scala
// First branch: free function `functions.when(c, v)` creates the entry-point Column
val head = when(toColumn(firstCond), toColumn(firstResult))
// Subsequent branches: chain via Column.when
val tail = branches.tail.foldLeft(head) { (acc, branch) =>
  acc.when(toColumn(branch._1), toColumn(branch._2))
}
// Terminate with .otherwise
tail.otherwise(toColumn(otherwise))
```

Empty `branches` degenerates to `toColumn(otherwise)` (mirrors SQL's `CASE WHEN FALSE THEN x ELSE y END`).

| Type | Layer | Why |

| Spark compile (Column.when / .as) | **connector** (`spark-connector/PortableExprCompiler.scala`) | Engine-specific |

## Spark concerns (per user directive + scala-spark-batch-bugs-mindset)

- **ZERO new spark imports** in `sm8-core/expr/Expr.scala` (the new cases are pure data; `Product with Serializable`)
- The Spark compile path uses only existing imports (`org.apache.spark.sql.functions.when` — already in the imports)
- **Mantra #1 (closure-safety)**: the `foldLeft` in `Expr.CaseWhen` runs in the driver; each `toColumn` is a pure function call
- **Mantra #5 (driver vs executor)**: every test in `PortableExprCompilerDataFrameSpec` runs entirely in the driver (build DataFrame + apply compiled Column + collect)
