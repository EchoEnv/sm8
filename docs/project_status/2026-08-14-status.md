## 2. What just landed — PR-C-final (#31) merged

PR-C-final adds:
- **`bannedDependencies=org.apache.spark:*` enforcer on `sm8-platform`** (cross-module consistency — all modules now ban Spark at build time).
- **Hand-built Restate v2.x `QueryService` handler class** — no v1.x static `Restate.run` (removed in v2.x), no annotation-driven `@Service` discovery (`@Handler` is `RetentionPolicy.SOURCE`; `@Service` is `@Deprecated(forRemoval=true)`). Discovery is via `ServiceDefinition.of(name, ServiceType.SERVICE, List(HandlerDefinition.of(...)))`.
- **`RestateBootstrap`** — `bindAndListen(model, registry, cache, port=8080): Int` (fire-and-forget; returns bound port).
- **5 new `QueryServiceSpec` tests** — drive through `HandlerRunner.run(stubContext, ...)` (no Docker, no Testcontainers). Verified via debug-mantra: the SDK's `run(ctx, reqSerde, resSerde, arCallback)` reads the request body from `ctx.request().body()` — encoded via `requestSerde.serialize(request)` + passed into the stub.
- **Typed `TerminalException`** in the handler body's error path — preserves the 11-subtype `EngineError` ADT's `ErrorCode` in the journal + retry path via an exhaustive `engineErrorCode(err)` mapping (503/504/422/501/...).
- **Explicit `ObjectMapper` with `DefaultScalaModule`** — `JacksonSerdeFactory.DEFAULT` doesn't reliably auto-load the Scala module via SPI.
- **4 new Maven deps** (pinned in parent `<dependencyManagement>`): `dev.restate:sdk-{api,common,core,http-vertx,serde-jackson}:2.1.1`, `jackson-module-scala_2.13:2.15.2`, `io.vertx:vertx-core:4.5.11`.
- **Restate SDK v2.x is fully state-machine-driven** — journaled sub-calls are `HandlerContext.submitRun(...)` (async, requires `@Service` `@Handler` method + configured serde). The handler body is the synchronous `(CTX, REQ) => RES` function passed to `HandlerRunner.of(...)`.

**Post-merge state**:
- `mvn -pl sm8-core scalatest:test` → 181 succeeded
- `mvn -pl sm8-platform scalatest:test` → 146 succeeded
- enforcer: `Rule 0 ... passed` on both core + platform
- Cross-module: every reactor maven module now uses the enforcer (`sm8-core`, `sm8-platform`, `connectors/*`, `plugins/*`, `sm8-cli`).

## 5. Strict-skill application — what was applied to PR-C-final

Per the project's mandate (MEMORY.md: "All memories are STRICT RULES, not suggestions"):

- **karpathy-guidelines-mindset** — surgical: 1 enforcer rule + 4 deps + 1 new class + 1 helper + 5 tests; nothing pre-existing touched. Scope-pivot from "wrap Restate.run" to "hand-built ServiceDefinition" because v2.x dropped the v1.x API.
- **debug-mantra-mindset** — found that the SDK's `HandlerRunner.run` reads the request body from `ctx.request().body()` (not from a separate argument). The stub `HandlerRequest` had an empty body → SDK threw `"No content to map due to end-of-input"`. Fix: encode the request via `requestSerde.serialize(request)` and feed the `Slice` into the stub.
- **scala-data-driven-refactor-mindset** — `object` (not trait) for `RestatedEngineRunner`; `engineErrorCode(err)` is a sealed-trait match (compiler-enforced exhaustiveness on the 11-subtype `EngineError`).
- **scala-jvm-safety-mindset** — `Either` at engine boundary; `RuntimeException` only at the wire boundary (after the typed-error ADT is preserved via `TerminalException`); `@transient inflight + readResolve` from PR-C5b-ext-β ensures the cache survives journal rehydration.
- **scala-error-handling-mindset** — `EngineError.toString` was the v1.x wrapping; now `engineErrorCode(err)` returns the typed HTTP code (503 EngineUnavailable, 504 QueryTimedOut, 422 DecimalOverflow, etc.).
- **scala-impact-analysis-mindset** — named every caller: `RestateBootstrap` (production bind) + `QueryServiceSpec` (test invocation). 0 production callers in the reactor today.
- **scala-jar-packaging-mindset** — `<dependencyManagement>` pinned all 4 new deps in parent pom for cross-module reproducibility. Verified no `org.apache.spark:*` transitive via JAR inspection.
- **scala-spark-batch-bugs-mindset** — latent `MCPEngineProvider.query` determinism risk under journal replay remains; flagged as a follow-up (the engine-portable path doesn't enable this yet, but the journaled handler will when PR-C-final-int ships).
- **scala-perf-testing-mindset** — N/A (no benchmark in this PR; the cache HIT path is the dominant production case).
- **git-pr-workflow** — branch + 3 commits + squash-merge + after-merge cleanup (local + remote-tracking branches pruned).
- **codegraph-pr-gate** — codegraph blast-radius check + 2 specialist reviewer agents (DE + architect/JVM-safety) surfaced 16 findings.
